# 16. Agent 实施流程与验收

### 16.1 推荐执行顺序

1. 读取 `AGENT_HANDOFF.md` 与核心视觉约束。确认当前任务和项目框架，通过路由只读所需规范章节、组件指南、Token 与参考图；不全文预加载整个组件库。
2. 页面任务先接入 Token 与背景，按需要实现顶栏、左栏、主区和阅读面，校准 R1 的整体比例；单组件任务直接进入该组件，不额外搭建后台页面。
3. 制作当前任务涉及的基础组件或效果，复用真实用法，按适用参考检查状态与皮肤。
4. 组合需要的页面内容，接入真实数据或明确标记的本地模拟状态，不复制演示数值作为业务常量。
5. 仅为当前范围完成搜索、筛选、分页、选择、导入、切换与键盘操作，按相关契约处理失败和竞态。
6. 检查所有目标视口、长文本、减少透明度、减少动效和字体回退。
7. 运行 Token 校验；在浏览器渲染并与参考图同视口 / 同状态对照。只声明实际执行过的验证。

### 16.2 必须通过的结果

- 左导航、整行顶栏、右上三个入口和主区比例与 R1 一致。
- 既能看见玻璃透色、亮边和柔影，也能稳定读清文字。
- 颜色、尺寸、阴影来自统一 Token；没有同义样式在多个页面漂移。
- 下拉、表格横滚、焦点环和弹窗不裁切；最上层关闭顺序正确。
- 默认、悬停、选中、聚焦、加载、禁用、错误、只读均有正确且可分辨的结果。
- 搜索、筛选、分页和返回焦点可用；切换上下文不显示旧租户响应。
- 导入完成与扫描通过分别呈现；服务端失败不能显示为成功。
- 在 360 px 与 200% 缩放下关键功能仍能到达；桌面没有意外的 body 横滚。

### 16.3 交付报告

编码 Agent 应返回：实现的页面与组件、关键复用点、运行方法、实际验证过的视口 / 状态、参考图差异和剩余范围。不能把“源码中写了样式”当成“视觉已经验证”。

本包交付的是规范、样式基础和可复用模板；CSS 与 Token 的一致性校验不等于一个真实业务网站已经完成。具体站点的视觉与交互仍需在其实际字体、浏览器、背景和数据下验收。

更详细的操作清单见 `ACCEPTANCE.md`，复杂组件的 API / 状态关系见 `COMPONENT_CONTRACTS.md`。
