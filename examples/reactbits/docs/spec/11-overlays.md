# 11. 下拉、浮层与弹窗

### 11.1 几何与层级

| 组件 | 桌面宽度基准 | 内边距 | 材料 |
|---|---:|---:|---|
| 行内更多菜单 | 200–240 px | 8 px | popover |
| 简单筛选下拉 | 至少等于触发器，通常 224 px | 8 px | popover |
| 待办面板 | 420 px | 20 px | popover |
| 租户与空间切换 | 360 px | 20 px | popover |
| 用户信息面板 | 320 px | 20 px；操作列表可局部减小 | popover |
| 导入弹窗 | 520 px | 24 px | dialog |
| 操作确认 | 400 px | 24 px | dialog |

浮层距触发器 8 px，距视口边缘至少 16 px；优先下方靠右或按触发器方向对齐，碰撞时翻转 / 平移。宽度上限为 `calc(100vw - 32px)`，高度上限为可用视口减去边距，内部可滚动。定位使用实际触发器几何或成熟浮层原语，不写死页面坐标。

箭头属于可选装饰；如果实现，约 8 px，颜色与浮层一致，不影响点击和对比度。触发器移动、容器滚动、浏览器缩放或视口变化时，浮层必须更新位置或按契约关闭。

层级按 Token 使用，关系必须满足：页面内容 < 吸顶局部内容 < 顶栏 < 普通下拉 < 抽屉遮罩 < 抽屉 < 模态遮罩 < 模态 < 模态内子浮层 < Toast。数值不能替代正确的 stacking context；在原生 `<dialog>` top layer 中的子菜单需挂到相应对话框内，不能假定 body 的高 `z-index` 能覆盖 top layer。

### 11.2 三个顶栏入口

**待办面板：** 标题和数量、待处理 / 已完成切换、最多三个预览条目、每条图标 / 标题 / 空间说明 / 状态、底部总数与“查看全部待办”。它包含多个控件和内容，是非模态面板，不是单纯 `role="menu"`。数据可以滚动或分页，不在每次打开时把焦点自动抢到背景页面。

**租户与空间面板：** 组织搜索、组织列表、角色标签、当前组织下的空间、管理入口。当前项以浅绿和勾选显示。选择其他组织后加载其空间；最终切换组织和空间作为一个明确事务处理，失败保持原租户上下文并给出反馈。名称、空间和权限不能短暂显示为不同组织的混合数据。

**用户信息面板：** 头像、名称、账号说明和角色；个人资料、账号安全、偏好设置、帮助中心；分割后的退出。退出采用中性强调，不默认使用删除式红色。偏好子菜单必须支持键盘进入、退出和边缘碰撞。

三个顶栏面板互斥打开。图 R2 同时展示三组面板仅用于说明样式，不作为产品交互要求。

### 11.3 导入弹窗

导入弹窗包含：标题 / 说明、来源分段（软件包 / Git 仓库 / 资源 URL）、对应来源输入区、文件或来源校验结果、技能名称、取消与导入。来源变化应切换为真实的来源字段，不只是改变按钮颜色。

软件包区域采用低对比虚线边框和上传图标，说明允许格式；已选文件卡片显示文件名、大小、移除操作和准确状态。文件类型、体积等规则来自平台配置，不能仅因参考图写了 ZIP / TAR.GZ 就假定后端支持。

客户端初检、服务端接收、导入完成、安全扫描、可启用分别反馈。进行中的可取消阶段和不可取消阶段按服务端能力表达。失败保留用户输入，提供可操作的错误信息与重试，不清空全部表单。

真实模态框需要遮罩、标题关联、关闭入口、焦点管理和背景不可交互。R4 没有展示整页遮罩，不代表实现应省略遮罩。使用 `aria-modal` 只表达已经实现的模态行为。[W3C Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

### 11.4 确认与危险操作

停用是可恢复但影响服务的动作，使用警告图标与沙金确认按钮，并说明影响、是否可恢复。删除与不可逆动作使用危险语义，并说明具体对象和影响。不能把所有确认按钮都做成相同绿色。

确认框按钮文字必须具体，例如“确认停用”“删除技能”；避免只有“确定”。需要避免误操作时，初始焦点放在取消或说明区域；默认不让 Enter 在尚未理解提示时执行破坏动作。确认之前保留原列表状态；请求成功后再更新，失败留在当前上下文。
