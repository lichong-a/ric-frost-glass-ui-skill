# 11. 下拉、浮层与弹窗

### 11.1 几何与层级

| 组件 | 桌面宽度基准 | 内边距 | 材料 |
|---|---:|---:|---|
| 行内更多菜单 | 200–240 px | 8 px | popover |
| 简单筛选下拉 | 至少等于触发器，通常 224 px | 8 px | popover |
| 待办面板 | 420 px | 20 px | popover |
| 租户与空间切换 | 360 px | 20 px | popover |
| 用户信息面板 | 320 px | 20 px；操作列表可局部减小 | popover |
| 导入弹窗 | 520 px | 24 px | dialog |
| 操作确认 | 400 px | 24 px | dialog |

浮层距触发器 8 px，距视口边缘至少 16 px；优先下方靠右或按触发器方向对齐，碰撞时翻转 / 平移。宽度上限为 `calc(100vw - 32px)`，高度上限为可用视口减去边距，内部可滚动。定位使用实际触发器几何或成熟浮层原语，不写死页面坐标。

箭头属于可选装饰；如果实现，约 8 px，颜色与浮层一致，不影响点击和对比度。触发器移动、容器滚动、浏览器缩放或视口变化时，浮层必须更新位置或按契约关闭。

层级按 Token 使用，关系必须满足：页面内容 < 吸顶局部内容 < 顶栏 < 普通下拉 < 抽屉遮罩 < 抽屉 < 模态遮罩 < 模态 < 模态内子浮层 < Toast。数值不能替代正确的 stacking context；在原生 `<dialog>` top layer 中的子菜单需挂到相应对话框内，不能假定 body 的高 `z-index` 能覆盖 top layer。

### 11.2 三个顶栏入口

**待办面板：** 标题和数量、待处理 / 已完成切换、最多三个预览条目、每条图标 / 标题 / 空间说明 / 状态、底部总数与“查看全部待办”。它包含多个控件和内容，是非模态面板，不是单纯 `role="menu"`。数据可以滚动或分页，不在每次打开时把焦点自动抢到背景页面。

**租户与空间面板：** 组织搜索、组织列表、角色标签、当前组织下的空间、管理入口。当前项以浅绿和勾选显示。选择其他组织后加载其空间；最终切换组织和空间作为一个明确事务处理，失败保持原租户上下文并给出反馈。名称、空间和权限不能短暂显示为不同组织的混合数据。

**用户信息面板：** 头像、名称、账号说明和角色；个人资料、账号安全、偏好设置、帮助中心；分割后的退出。退出采用中性强调，不默认使用删除式红色。偏好子菜单必须支持键盘进入、退出和边缘碰撞。

三个顶栏面板互斥打开。图 R2 同时展示三组面板仅用于说明样式，不作为产品交互要求。

### 11.3 导入弹窗

导入弹窗包含：标题 / 说明、来源分段（软件包 / Git 仓库 / 资源 URL）、对应来源输入区、文件或来源校验结果、技能名称、取消与导入。来源变化应切换为真实的来源字段，不只是改变按钮颜色。

软件包区域采用低对比虚线边框和上传图标，说明允许格式；已选文件卡片显示文件名、大小、移除操作和准确状态。文件类型、体积等规则来自平台配置，不能仅因参考图写了 ZIP / TAR.GZ 就假定后端支持。

客户端初检、服务端接收、导入完成、安全扫描、可启用分别反馈。进行中的可取消阶段和不可取消阶段按服务端能力表达。失败保留用户输入，提供可操作的错误信息与重试，不清空全部表单。

真实模态框需要遮罩、标题关联、关闭入口、焦点管理和背景不可交互。R4 没有展示整页遮罩，不代表实现应省略遮罩。使用 `aria-modal` 只表达已经实现的模态行为。[W3C Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

### 11.4 确认与危险操作

停用是可恢复但影响服务的动作，使用警告图标与沙金确认按钮，并说明影响、是否可恢复。删除与不可逆动作使用危险语义，并说明具体对象和影响。不能把所有确认按钮都做成相同绿色。

确认框按钮文字必须具体，例如“确认停用”“删除技能”；避免只有“确定”。需要避免误操作时，初始焦点放在取消或说明区域；默认不让 Enter 在尚未理解提示时执行破坏动作。确认之前保留原列表状态；请求成功后再更新，失败留在当前上下文。

### 11.5 弹窗类型与选择

先判断是否需要阻断当前操作，再按任务长度选形态。所有类型沿用同一霜玻璃、标题、正文、操作区和状态色，不因名称不同新增一套视觉体系。

| 类型 | 什么场景使用 | 结构与尺寸 | 关闭与确认规则 |
|---|---|---|---|
| 提示 / 说明 Dialog | 用户需要阅读一段影响当前任务的说明 | 520 px；标题、正文、关闭入口 | 通常允许 Escape 和关闭按钮；无需用户处理的短信息用 Toast |
| 操作确认 Dialog | 提交前确认对象、范围和后果 | 400 px；具体对象、取消和明确动作 | 初始焦点避免默认执行危险动作；确认结果来自真实操作 |
| 危险 / 阻断 Alert Dialog | 必须立即决定的删除、不可逆或关键失败 | 400 px；风险、后果、恢复说明 | 已实现模态时可用 `alertdialog`；默认不靠点击遮罩关闭，保留取消或明确处理入口 |
| 表单 / 创建 / 编辑 Dialog | 一次可完成的短表单 | 520 px；较宽表单可用 720 px 宽版 | 字段错误就近显示；未保存退出按业务约定处理，不无声丢弃输入 |
| 导入 / 任务 Dialog | 文件校验、分阶段提交、任务进度与恢复 | 520 或 720 px；阶段、结果、失败和重试 | 关闭视图与取消任务分别表达；已有任务使用真实任务标识恢复 |
| 分步 / Wizard Dialog | 一个目标需要少量连续步骤 | 720 px；步骤、正文、上一步 / 下一步 | 保留已填状态；各步验证通过再继续，长流程优先独立页面 |
| 详情 / 阅读 Dialog | 临时查看完整说明或对象详情 | 720 px；阅读正文与必要操作 | 长内容局部滚动；需要持续对照列表时改用 Drawer |
| 媒体 / 全屏 Dialog | 图片、视频或较大预览必须使用主要视口 | 全屏尺寸仍保留 16 px 外边距与安全区 | 关闭始终可达；媒体有说明、错误状态与键盘浏览入口 |
| 非模态 Dialog | 用户需要保持背景可操作的临时辅助窗口 | 使用明确非模态原语和可见边界 | 不设置 `aria-modal`，不锁焦点，不让背景 inert |
| Popover / Menu / Tooltip | 锚点附近的就地信息、动作列表或纯文字提示 | 跟随锚点，按可用空间翻转 | 有控件的内容用 Popover；动作列表用 Menu；Tooltip 不包含可交互元素 |

普通 Dialog 使用 `aw-dialog`；确认使用 `data-kind="confirm"`，宽版 / 全屏分别使用 `data-size="wide|fullscreen"`。类型名称表达业务目的，不能据此臆造组件 Props。遮罩点击默认只适用于无未保存输入、无阻断风险的可关闭内容；提交、取消和关闭必须有独立状态。需要长时间专注、复杂路由或大量表单时选择独立页面。

### 11.6 上下左右抽屉

抽屉用于保留页面上下文，同时提供详情、选项或短操作。四个方向共享标题、关闭入口、正文和可选操作区；方向由业务位置和阅读任务决定。

| 方向 | 什么场景使用 | 几何规范 |
|---|---|---|
| 右侧 | 记录详情、属性编辑、与列表并排阅读 | 默认 420 px，受视口宽度限制；高度为可用视口 |
| 左侧 | 导航、目录、筛选入口；窄屏主导航 | 同一宽度规则；主导航沿用自身 sidebar Token |
| 上方 | 页面级短筛选或辅助选项，需要靠近顶部入口 | 全宽，按内容增长，最大 70dvh；避免覆盖正在使用的顶栏入口 |
| 下方 | 窄屏短动作、选项选择、就地补充信息 | 全宽，按内容增长，最大 70dvh；底部留安全区和输入法空间 |

共享外观入口为 `aw-drawer[data-side="left|right|top|bottom"]`，左右宽度读取 `drawer.width`，上下高度上限读取 `drawer.maxBlockSize`。示例的 `Dialog` 使用实际 `side` 参数支持四个方向；接入其他原语时按其真实 API 映射，不直接猜参数名称。

模态抽屉使用对话框语义、背景不可交互、焦点约束和返回位置；非模态详情抽屉保留背景操作，不设置 `aria-modal`。正文可以局部滚动，头尾操作保持可达；打开输入法时按可用视口重新计算。进入过渡遵循普通浮层的短时动效，不增加弹跳或整面透明度动画；减少运动时直接进入最终位置。

### 11.7 弹窗与抽屉的共同边界

只由最上层处理 Escape 和外部点击。打开新的模态前关闭无关菜单；子浮层属于当前模态的焦点与可访问上下文。使用原生 `<dialog>` 时，通知与子菜单的挂载点必须考虑 top layer，不能依赖更大的 body z-index 穿透原生模态。

加载、校验、提交、失败与成功分别呈现；请求中阻止重复提交，失败保留输入和恢复入口。关闭视图不能被解释成取消已提交任务。标题和说明通过真实 ID 关联；初始焦点、Tab 范围、关闭后的返回位置由交互原语完成，CSS 不承担这些行为。[W3C Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
