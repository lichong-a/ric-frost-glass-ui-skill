# 12. 反馈、加载与空状态

### 12.1 状态区分

| 状态 | 必须显示 | 恢复入口 |
|---|---|---|
| 首次无数据 | 明确“还没有技能”等事实、简短说明 | 创建 / 导入（有权限时） |
| 筛选无结果 | “未找到匹配的技能”、当前筛选提示 | 清空筛选 |
| 请求失败 | 失败信息，保留筛选和已有数据 | 重试 |
| 无权限 | 说明当前范围不可访问 | 可达的权限申请或返回入口 |
| 首次加载 | 与最终内容同布局的骨架 | 根据业务允许取消或等待 |
| 后台刷新 | 保留当前表格、小范围忙碌标识 | 失败后显示就近提示 |

空状态图标约 36–40 px，标题 18 px、描述 14 px；空间适度，不应让普通筛选空态占满整个屏幕。骨架沿用表格列结构和行高，避免数据出现后突然改变布局。骨架是占位装饰，隐藏于辅助技术；区域通过一次适当的忙碌状态表达加载。

### 12.2 Toast 与 Alert

Toast 使用霜玻璃表面、状态图标、简短文字和关闭按钮。桌面默认右上角避开顶栏，窄屏靠底部且避开安全区；同时最多三条，重复信息合并，不能遮住当前提交控件。

成功消息默认 5 秒后关闭；有操作入口的错误消息保持到用户处理或关闭，不自动消失。不要把长错误堆在 Toast；表单错误应就近显示，系统持续风险用页面 Alert。成功、失败反馈避免重复播报；普通完成提示使用温和的 live region，紧急错误才使用更强的通告。

“扫描完成后可启用”等提示是业务说明，应靠近相关状态或操作显示。不能让用户只能通过鼠标 hover 才知道为什么按钮禁用。
