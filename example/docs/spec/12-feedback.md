# 12. 反馈、加载与空状态

### 12.1 状态区分

| 状态 | 必须显示 | 恢复入口 |
|---|---|---|
| 首次无数据 | 明确“还没有技能”等事实、简短说明 | 创建 / 导入（有权限时） |
| 筛选无结果 | “未找到匹配的技能”、当前筛选提示 | 清空筛选 |
| 请求失败 | 失败信息，保留筛选和已有数据 | 重试 |
| 无权限 | 说明当前范围不可访问 | 可达的权限申请或返回入口 |
| 首次加载 | 与最终内容同布局的骨架 | 根据业务允许取消或等待 |
| 后台刷新 | 保留当前表格、小范围忙碌标识 | 失败后显示就近提示 |

空状态图标约 36–40 px，标题 18 px、描述 14 px；空间适度，不应让普通筛选空态占满整个屏幕。骨架沿用表格列结构和行高，避免数据出现后突然改变布局。骨架是占位装饰，隐藏于辅助技术；区域通过一次适当的忙碌状态表达加载。

### 12.2 Toast 与 Alert

Toast 使用霜玻璃表面、状态图标、简短文字和关闭按钮。桌面默认右上角避开顶栏，窄屏靠底部且避开安全区；同时最多三条，重复信息合并，不能遮住当前提交控件。

成功消息默认 5 秒后关闭；有操作入口的错误消息保持到用户处理或关闭，不自动消失。不要把长错误堆在 Toast；表单错误应就近显示，系统持续风险用页面 Alert。成功、失败反馈避免重复播报；普通完成提示使用温和的 live region，紧急错误才使用更强的通告。

“扫描完成后可启用”等提示是业务说明，应靠近相关状态或操作显示。不能让用户只能通过鼠标 hover 才知道为什么按钮禁用。

### 12.3 角落 Notice 与通知位置

Toast 用于短结果；Notice 用于需要标题、说明、相关对象或后续操作的通知。Notice 不能代替必须阻断处理的 Dialog，也不能成为持续风险的唯一记录。

| 类型 | 什么场景使用 | 内容与生命周期 |
|---|---|---|
| 成功 Toast | 一个明确操作已完成 | 一句真实结果；默认 5 秒，悬停或内部焦点暂停计时 |
| 信息 Toast | 非阻断的短提示 | 一句提示，可关闭；需要操作时改为 Notice |
| 成功 / 信息 Notice | 后台任务结束、结果待查看或协作提醒 | 标题、简短说明、对象、查看入口；默认持续到处理或关闭 |
| 警告 / 错误 Notice | 操作失败、连接失效或需要恢复 | 原因、影响、重试 / 恢复入口；不自动消失 |
| Inline Message / Alert | 字段、当前数据区或系统持续异常 | 与受影响内容同处；错误解决前常显 |
| Banner / 公告 | 影响整个页面的维护、配置或组织提示 | 位于相应页面上下文，允许按业务规则关闭；不模拟成角落短通知 |

角落通知的内容宽度分别读取 `toast.width` / `notice.width`。外边距桌面 24 px、窄屏 16 px，并取安全区更大值。桌面默认右上角并避开顶栏；允许左上、右上、左下、右下。`data-placement="top-start|top-end|bottom-start|bottom-end"` 分别对应这些位置（LTR）；RTL 按逻辑方向镜像。窄屏将顶部通知移到同侧底部，避开底部导航、输入控件和安全区。

一个任务范围只使用一个通知栈，同时最多显示三条，按稳定 ID / operationId 去重；更多消息进入可查看的通知列表。顶部栈向下、底部栈向上扩展；关闭后只让同栈条目回补。通知不挤动页面布局，不抢焦点；鼠标事件仅作用于消息卡，不能用整屏透明容器遮挡页面。

普通完成与信息使用温和的状态播报；紧急错误按实际必要性使用 alert。同一消息只播报一次，不逐帧播报进度或倒计时。关闭后保留必要的任务记录；“再次尝试”应复用安全的真实业务操作，不重复可能已经完成的写入。
