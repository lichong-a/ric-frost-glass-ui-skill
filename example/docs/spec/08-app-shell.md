# 8. 页面框架与响应式

### 8.1 桌面布局

标准实现视口为 **1728 × 900 CSS px**。参考图 R1 为 1734 × 907 图像像素，设备像素比未知；1728 × 900 是便于实现的接近基准。需要逐项图像比较时另渲染 1734 × 907，并记录缩放方法，不能用不同视口直接判断像素误差。

| 区域 | 规范 |
|---|---|
| 应用外壳 | `min-width: 0`，桌面高度使用 `100dvh`；水平 16 px、垂直 8 px 外边距 |
| 顶栏 | 64 px 高，独占整行；Logo 靠左，待办 / 租户空间 / 个人信息靠右 |
| 工作区 | 顶栏下间隔 12 px；两列：256 px 侧栏 + 自适应主区；列间隔 20 px |
| 左侧栏 | 24 px 圆角；独立滚动的导航内容 + 底部收起导航 |
| 主工作区 | 28 px 圆角；内边距 20 px；宽度使用剩余空间，不居中限制成窄卡片 |
| 页面头 | 面包屑在上；左侧主标题和说明；右侧次操作、主操作 |
| 工具栏 | 搜索、生命周期分段、来源、风险、扫描状态、标签管理；允许整组换行 |
| 数据区域 | 工具栏之后 20–24 px；数量、表头、数据行、分页放在同一阅读面 |

顶栏不重复显示第二份侧栏品牌；左导航不挤占顶栏整行。主标题不能和按钮黏在一起，也不能在宽屏无理由把操作按钮移到页面底部。

建议结构：

```html
<html class="aw-theme" lang="zh-CN">
  <body class="aw-app-page">
    <div class="aw-canvas aw-canvas-layer" aria-hidden="true"></div>
    <div class="aw-app-shell">
      <header class="aw-topbar"><!-- 品牌与三个顶栏入口 --></header>
      <div class="aw-workspace">
        <aside class="aw-sidebar" aria-label="主导航"><!-- 导航 --></aside>
        <main class="aw-main" id="main-content"><!-- 页面头、工具栏、数据 --></main>
      </div>
    </div>
    <div id="overlay-root"><!-- 下拉、对话框、通知，由交互层管理 --></div>
  </body>
</html>
```

这是结构示意，省略了内容和交互。`theme.css` 的实际类名以文件中的注释为准。框架存在时使用已有 Portal 和弹窗原语，不因示意结构重写应用入口。

### 8.2 导航

一级分组由分组名称与展开箭头组成；导航行高 44 px，左右内边距 12 px。常规项用透明底；hover 使用轻度浅米或浅茶绿；当前项用浅茶绿底、左侧约 3 px 深绿色竖条和较强文字共同标识，设置 `aria-current="page"`。

底部收起按钮与主体间用细分割线隔开。折叠后侧栏宽 72 px，保留可理解的图标与名称提示；通过键盘聚焦也能获得文字名称。折叠状态不能只留下无标签的装饰图标。

### 8.3 工具栏

搜索框桌面理想宽度约 360–440 px，最小 240 px，可用剩余空间缩放。筛选项最小约 112 px；生命周期分段作为完整一组。空间不够时先让工具栏换行，不挤压输入文字、不缩小字号、不让按钮溢出。

在 1440 px 左右出现两行工具栏是合理结果。不要为强行复刻 R1 的单行状态，设置全页面最小宽度 1728 px。清空筛选作用域必须由按钮文字与状态明确；条件变化后返回第 1 页。

### 8.4 断点

以下是补充的实现规则，原图未提供移动端。

| 视口 | 导航 | 顶栏 / 内容 | 表格 |
|---|---|---|---|
| ≥ 1280 px | 默认展开 256 px，用户可折叠 | 保留三个带文字入口；标题与操作并列 | 完整表格，按需横滚 |
| 1024–1279 px | 默认图标栏 72 px | 工具栏按组换行；顶栏入口可缩短副文案 | 保持列语义，不压扁字体 |
| 768–1023 px | 隐藏侧栏，入口打开抽屉 | 文档流布局；标题与操作可分行；主内容内边距 16 px | 横向滚动容器 |
| < 768 px | 触屏抽屉；关闭后焦点返回入口 | 品牌压缩；待办可仅图标+数量；租户与账户移入有名称的工作区入口 | 保留名称 / 状态 / 操作；其余字段通过横滚或明确的详情展开查看 |

移动端不应同时保留三个完整顶栏大按钮挤占品牌；合并入口必须仍能访问待办、租户、空间和账户。不得悄悄删除业务能力。表格转卡片不是默认行为，只有业务明确要求时才设计该变体。

最小验收宽度 360 px，另测 390 px、768 px、1024 px、1440 px 和 1728 px。任何视口都不能让整个页面水平滚动；表格内部横向滚动是允许的。

### 8.5 滚动与高度

桌面默认由主内容区承担纵向滚动，侧栏导航独立滚动，body 不滚动。表格按内容自然增高，包装层只用于必要的横向滚动，默认不强行吸顶表头。

若业务启用“固定表格可视高度”变体，由 `TableViewport` 同时承担纵横滚动，分页留在其外部，表头在该滚动容器内吸顶；此时主区不再增加第二个同方向滚动区。不要在仅设置 `overflow-x: auto` 的包装器里无条件声明吸顶表头并假定它会相对主区生效。

小于 1024 px 时切换为文档纵向滚动，避免小屏多重滚动。高度过小、200% 缩放或大量筛选条件换行时，内容必须仍可到达；不得被固定高度外壳截掉。
